## 主动修正与体验变化

- 无需原站登录；本地保存、备份、导入／导出。
- 满包时保留未采完矿物，掉落不按短计时器消失。

- 暂停、死亡、剧情和结局由显式状态管理，未照搬旧版弹窗与服务器逻辑。

## 2026-10-25：恢复原版拾取飘字与相关计分规则

本轮对照原始 ActionScript 的计分路径，修正已确认的差异：

| 行为 | 原版依据 | 本轮修正 |
| --- | --- | --- |
| 普通矿物拾取 | `Mineral.as` 读取物品售价，加到 Score，再创建 ScoreBox | 9 种矿物分别加 50／100／150／250／400／800／1500／2500／5000 分；直接挖取与掉落拾取共用奖励入口 |
| 数字飘字 | `ScoreBox.as` 显示 `+` 加积分，50 帧消退、每帧上升 1px | 恢复 `+50` 等数值，不再显示 `+煤炭`；按 30fps 等效速度上升／消退 |
| 普通土层挖透 | `MapData.as::dig` 完成钻探且 isScore 为 true 时累加当前 Deep，不生成 ScoreBox | 补上深度计分；不会为普通泥土飘出伪矿物分数 |
| 特殊矿石 | 同样进入 Mineral 的售价计分路径 | 钛／硒／氪分别加 10000／20000／30000 分，重复触发无奖励 |
| 普通怪物 | `NPC.as::explode` 在非首领房间奖励 300 | 从错误的 100 改为 300；首领房间的普通召唤怪不奖励积分 |
| 大型与守门怪 | `BigDragon.as` 奖励 1000；`TileView.as` 将 ItemDragon 实例化为 BigDragon2 | 大型怪保持 1000，守门怪从错误的 100 改为 1000，补上击败飘字 |
| 两类首领 | `Boss.as` / `SubBoss.as` 奖励 10000 并显示 ScoreBox | 保留 10000，补上数字反馈 |
| 超威力炸弹 | `TileView.as::createBomb` 在成功放置 Dinamite 时加 5000 | 加分由爆炸时移到成功放置时，失败／爆炸均不重复加分 |
| 出售与金币奖励 | `Inventory.as::sell` 才增加矿物出售金币；`BonusBox.as` 单独显示金币获得提示 | 出售不重复加积分；金币掉落改为中文金币提示，不混用积分飘字；补给道具不按售价加分 |

`awardScore` 负责计分与可选积分事件；`collectItem` 只用于真实拾取。商店购买、装载存档继续使用不奖励积分的库存入口。满背包不会产生拾取奖励，失败的掉落仍保留。既有存档格式不变，旧积分保留，不按不完整的历史库存猜测补分。

验证：`npm run check` 与全部 20 项检查通过，新增 5 项覆盖上述规则、出售后的积分不变、重复拾取、满包、购买不加分、存档往返与失败放弹。独立 QA 浏览器从新游戏按住方向键挖到第一块煤，实际看到 `+50`、SCORE 56、背包进度 1/2、金币 0；其中 6 分来自沿途完成钻探的深度奖励。证据 `docs/evidence/score-coal-50.jpg` 来自实际键盘输入，无注入游戏状态。
